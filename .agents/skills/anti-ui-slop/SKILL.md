# Anti-UI-Slop Skill

AI-generated UIs suffer from predictable failure modes: generic gradients,
"Transform your workflow" hero copy, blue primary buttons, and layouts that
look like every other SaaS landing page.

This skill is a systematic detector and fixer for those patterns.

---

## What is UI Slop?

UI slop is the aesthetic footprint of zero design decisions. It occurs when:
1. Components assembled from defaults with no visual personality.
2. Copy written to sound professional rather than say something true.
3. Colors default to the framework primary blue.
4. Spacing is uniform (8px grid everywhere) with no visual rhythm.
5. Every section uses the same layout pattern.

**The test:** Could this component belong to any fintech SaaS? If yes — it is slop.

---

## The 10-Point Slop Audit

Rate each 0-10. Score <= 7 requires intervention.

### 1. Copy Authenticity (0-10)
Slop markers:
- "Transform your workflow/business/experience"
- "Powerful, flexible, and easy to use"
- "Trusted by N+ teams worldwide"
- Any headline ending in "at scale"

10 looks like: Specific, verifiable claims with numbers.
❌ "Comprehensive insurance intelligence platform"
✅ "IRDAI filing analysis in 40 seconds, not 4 hours"

### 2. Visual Hierarchy (0-10)
Slop markers:
- Same font weight for heading and subheading
- Card grid with equal visual weight on every card

10 looks like: Clear primary/secondary/tertiary rhythm; one dominant element per section.

### 3. Color Intentionality (0-10)
Slop markers:
- Primary button is #3B82F6 (Tailwind blue-500)
- Background is pure white #FFFFFF
- More than 4 distinct colors visible at once

10 looks like: A palette with a story. StatIQ warm canvas + ink + rust = editorial intelligence.

### 4. Layout Originality (0-10)
Slop markers:
- Alternating icon-left / icon-right feature rows
- 3-column symmetric feature grid
- Full-width hero with centered text + two buttons

10 looks like: Editorial layouts — numbered sections, pull quotes, asymmetric columns.

### 5. Whitespace Use (0-10)
Slop markers:
- Equal padding on every section (py-20 everywhere)
- No visual breathing room between content clusters

10 looks like: Deliberate rhythm — some sections breathe, some dense. Contrast creates interest.

### 6. Interaction Design (0-10)
Slop markers:
- Hover state is just opacity-75
- No micro-interaction on primary CTA
- Form fields have browser-default focus only

10 looks like: Subtle, purposeful motion. Primary CTA lifts on hover.

### 7. Data Presentation (0-10)
Slop markers:
- Numbers without context (just "24,500" with no unit)
- Tables with no sorting, no empty state
- Charts with default library color palette

10 looks like: Every number has unit + trend indicator + comparison baseline.

### 8. Mobile Experience (0-10)
Slop markers:
- Desktop layout squished to 375px
- Touch targets < 44px

10 looks like: Mobile layout designed independently, not derived from desktop.

### 9. Typography Craft (0-10)
Slop markers:
- Line-height is browser default
- Letter-spacing not set on headings
- Font size jumps from h1 to h3 with no scale

10 looks like: Complete type scale. Headings at -0.02em tracking. Body at 1.6 line-height.

### 10. Distinctiveness (0-10)
Ask: Would a designer who saw 100 landing pages remember this one?

Slop markers:
- Nothing here couldn't have been generated by a template
- No visual risk taken anywhere

10 looks like: One memorable design choice that could only belong to StatIQ.

## Common Slop Fixes for StatIQ

### Fix: Generic Hero -> Editorial Hero
```tsx
// Slop
<section className="text-center py-24">
  <h1 className="text-5xl font-bold text-blue-900">Insurance Intelligence Platform</h1>
  <button className="mt-8 px-8 py-3 bg-blue-500 text-white rounded-lg">Get Started</button>
</section>

// Anti-slop
<section className="grid grid-cols-[1fr_auto] gap-8 pt-16 pb-12">
  <div>
    <span className="text-sm font-medium tracking-widest text-[--color-accent-warm] uppercase">
      Intelligence Layer
    </span>
    <h1 className="font-heading text-6xl font-bold text-[--color-ink] mt-3 leading-[1.05]">
      IRDAI filings.<br/>Decoded in 40s.
    </h1>
  </div>
</section>
```

### Fix: Feature Grid -> Numbered Editorial Rows
```tsx
// Slop — symmetric 3-col grid
<div className="grid grid-cols-3 gap-6">
  {features.map(f => <FeatureCard key={f.id} {...f} />)}
</div>

// Anti-slop — numbered editorial rows
<ol className="divide-y divide-[--color-border]">
  {features.map((f, i) => (
    <li key={f.id} className="grid grid-cols-[3rem_1fr_auto] gap-6 py-8">
      <span className="text-4xl font-mono text-[--color-accent-warm] opacity-40">
        {String(i + 1).padStart(2, "0")}
      </span>
      <h3 className="font-heading text-xl font-semibold">{f.title}</h3>
    </li>
  ))}
</ol>
```

### Fix: Blue CTA -> Brand CTA
```tsx
// Slop
<button className="bg-blue-500 hover:bg-blue-600 text-white px-6 py-3 rounded-lg">Get Started</button>

// Anti-slop
<button className="bg-[--color-accent-warm] text-white px-6 py-3 rounded hover:brightness-110 active:scale-95 transition-all duration-150 font-medium tracking-wide">
  Start free analysis
</button>
```

## Non-Negotiable Rules

- No default Tailwind blue (blue-*) anywhere in user-facing StatIQ components.
- No generic CTA copy — every button says what happens when clicked.
- No empty sections — every section earns its space with specific content.
- No symmetric grids for more than 2 rows — introduce visual breaks.
- One memorable design choice per major section — take at least one intentional risk.

---

## Audit Workflow

1. Score each dimension 0-10.
2. Flag any dimension <= 7 as requiring intervention.
3. Fix the lowest-scoring dimension first.
4. Re-score after fixing.
5. Ship only when every dimension >= 8.
